## Why geo is disabled
Previous production flow attempted geo backfill during assign and caused database statement timeouts.
To stabilize the pipeline, geo enrichment was removed from the critical runtime path.

## Current safe assign mode
The `/api/events/assign` route now:
- validates `x-ingest-secret`
- runs `assign_events_until_done_v8`
- does not call geo backfill RPC in production flow
- returns execution metadata for monitoring

Recommended safe payload:

{
  "mode": "assign",
  "batch_size": 20,
  "max_loops": 1,
  "stop_when_unchanged_loops": 1,
  "geo_backfill_limit": 0,
  "max_age": "30 days"
}
